基礎篇

認識 Kali Linux

Kali Linux 是由 OffSec 維護、以 Debian 為基礎的發行版，預載數百種資安工具，常用於滲透測試、數位鑑識與資安研究。

它是專業人員在「取得授權」前提下使用的工作平台，不適合當作日常主力系統。

安裝方式

虛擬機（最推薦）
用 VirtualBox、VMware 或 UTM 執行，可隨時快照還原。官方提供預建映像檔，下載後匯入即可。
WSL2
Windows 10/11 可執行 wsl --install -d kali-linux，適合只需要命令列工具的情況。
Live USB
從 USB 開機試用，不改動硬碟，適合臨時使用與鑑識。
實體安裝
裝在專用電腦上，可直接使用外接硬體，但需自行處理雙系統與備份。

只從官方網站 kali.org 下載，並校驗檔案完整性：

$ sha256sum kali-linux-*.iso

預建虛擬機的預設帳號與密碼皆為 kali，首次登入後請用 passwd 修改。

初始設定

Kali 採滾動更新，安裝後先更新系統。自 2020.1 起預設使用一般使用者，需要權限時再加 sudo，不建議長期以 root 操作。

$ sudo apt update && sudo apt full-upgrade -y
$ passwd
$ sudo apt install -y kali-linux-default   # 精簡版（如 WSL）選用

常用指令

pwd                # 顯示目前目錄
ls -la             # 列出檔案（含隱藏檔）
cd ~/Documents     # 切換目錄
cat notes.txt      # 檢視檔案
nano notes.txt     # 編輯檔案
sudo <指令>       # 以管理員權限執行
ip a               # 查看網路介面與 IP
ping -c 4 8.8.8.8  # 測試網路連線
apt search 關鍵字   # 搜尋套件
man <指令>        # 查看說明手冊

常見工具

Nmap
網路探索與連接埠掃描，了解網路上有哪些主機與服務。
Wireshark
圖形化封包分析，學習網路協定的好幫手。
Burp Suite
Web 測試用的代理工具，可檢視並修改 HTTP 請求。
Metasploit
漏洞驗證框架，只在自建或已授權的測試環境使用。
John the Ripper / Hashcat
評估密碼強度，用於稽核自己的雜湊資料。
Aircrack-ng
檢查自家無線網路的加密設定是否夠強。

例如，對自己架設的靶機做服務探測：

$ nmap -sV 192.168.56.101

先取得授權。掃描與測試只能針對自己擁有、或已取得書面授權的系統。

合法練習環境

  • 在虛擬機架設 Metasploitable 作為靶機，網路模式選「僅限主機」或「內部網路」，避免連到真實網路。
  • DVWA、OWASP Juice Shop：刻意設計有弱點的 Web 應用。
  • TryHackMe、Hack The Box：線上靶場與引導式課程。
  • VulnHub：可下載的弱點靶機映像。

基礎學習路線

  1. 熟悉 Linux 基礎與檔案權限
  2. 學習網路基礎：TCP/IP、DNS、HTTP
  3. 認識常見弱點類型，例如 OWASP Top 10
  4. 在靶機環境練習各種工具
  5. 撰寫測試報告與修補建議
  6. 考取認證（如 Security+、eJPT），參與合法的漏洞賞金計畫

工作環境與紀錄

專業測試靠的是流程：固定的目錄結構、完整的操作紀錄，以及隨時能還原的快照。

$ mkdir -p ~/lab/{scans,notes,evidence,report}
$ sudo apt install -y tmux
$ tmux new -s lab                    # 可分割視窗；Ctrl+b d 暫離
$ script -a ~/lab/notes/session.log   # 記錄終端機操作

做重大變更前先建立虛擬機快照，出問題時一鍵還原。

隔離的虛擬網路

理想的實驗室把 Kali、靶機與觀察用的機器放在與真實網路隔離的同一網段：

Kali（網卡 1：NAT 上網／網卡 2：僅限主機）
 ├─ 靶機：Metasploitable、DVWA
 └─ 觀察機：Wireshark 或 Security Onion
網段：192.168.56.0/24（僅限主機，不橋接到真實網路）

靶機只接內部網段、不給上網；每次練習前先還原乾淨快照，結果才可重現。

Nmap 進階用法

以下皆以自己的靶機（192.168.56.101）為例。

$ sudo nmap -sV -O 192.168.56.101           # 服務版本與作業系統偵測
$ nmap -p- -oA ~/lab/scans/full 192.168.56.101   # 全部埠，輸出三種格式
$ nmap -sC -sV -p 22,80 192.168.56.101       # 預設腳本 + 版本偵測
$ nmap --script-help default                   # 查看腳本說明

-oA 會同時產生 .nmap、.gnmap、.xml，方便日後比對與匯入其他工具。NSE 腳本分成多個類別，部分會主動測試弱點，使用前先讀說明，並確認有授權。

封包擷取與分析

$ ip a                                    # 確認網卡名稱
$ sudo tcpdump -i eth0 -w ~/lab/evidence/lab.pcap
$ wireshark ~/lab/evidence/lab.pcap &

Wireshark 常用的顯示篩選器：

ip.addr == 192.168.56.101               # 只看特定主機
dns                                     # DNS 查詢
http.request.method == "POST"           # 表單送出的請求
tcp.flags.syn == 1 && tcp.flags.ack == 0   # 只有 SYN：掃描的常見特徵

防守方可以從最後一條看出自己是否被掃描。從靶機端回頭觀察自己的測試動作，是理解偵測原理的好方法。

Web 應用測試與防禦

基本流程：把瀏覽器代理指向 Burp（127.0.0.1:8080），在 Proxy 檢視請求，用 Repeater 修改後重送，再對照 OWASP Top 10 檢查。靶機建議用 DVWA，把難度從 Low 調到 High，觀察防護如何讓同一類弱點失效。

注入（SQL、指令）
防禦：參數化查詢、嚴格的輸入驗證
跨站腳本（XSS）
防禦：輸出編碼、Content-Security-Policy
失效的存取控制
防禦：伺服器端授權檢查、最小權限
跨站請求偽造（CSRF）
防禦：CSRF token、SameSite cookie
伺服器端請求偽造（SSRF）
防禦：目的地允許清單、封鎖內網位址
驗證機制薄弱
防禦：多因素驗證、bcrypt 或 Argon2 雜湊、登入次數限制

替 Kali 做加固與稽核

Kali 自己也可能被攻擊，不要直接暴露在公網，並做好基本防護：

$ sudo apt install -y ufw lynis
$ sudo ufw default deny incoming && sudo ufw enable
$ systemctl list-unit-files --state=enabled   # 檢查開機自動啟動的服務
$ sudo lynis audit system                    # 系統安全健檢
  • SSH 改用金鑰登入並停用密碼登入
  • 實體機安裝時啟用全碟加密（LUKS）
  • 用完的服務就關掉，並定期更新

用 Bash 自動化

把掃描範圍寫進 scope.txt（只放已獲授權的目標），再用迴圈處理：

$ while read -r ip; do nmap -sV -oA ~/lab/scans/"$ip" "$ip"; done < scope.txt
$ grep "open" ~/lab/scans/*.gnmap          # 彙整所有開放的埠

用範圍檔管理目標，能避免誤掃到授權範圍之外的主機。

報告與授權規範

測試開始前先簽好書面授權，載明：

  • 範圍：哪些主機、網段與時間窗口
  • 禁止事項：例如阻斷服務、社交工程，除非明確同意
  • 資料處理：取得的資料如何保管與銷毀

報告至少包含：

  1. 執行摘要（給管理層看的結論）
  2. 範圍與方法
  3. 發現：嚴重度（可參考 CVSS）、影響、重現步驟、證據
  4. 修補建議與優先順序

若在實務中發現漏洞，請依「負責任揭露」流程通知相關單位，不要公開細節或濫用。

進階路線與認證

  1. 熟練 Nmap、Wireshark、Burp Suite，並能寫出完整報告
  2. 練習 Hack The Box、TryHackMe 的中階房間與 VulnHub 靶機
  3. 學習 Bash／Python 自動化，以及 Active Directory 與雲端環境基礎
  4. 考取認證：eJPT、PNPT 或 PenTest+，再挑戰 OSCP
  5. 也可走防守路線：Security+、SOC 分析與事件應變

其他

防禦視角：物理安全

資安不只發生在網路上。組織常見的物理安全措施包括：

  • 門禁與訪客管理：刷卡進出、訪客登記與陪同
  • 機房與網路設備上鎖，並設置監視攝影機
  • 管制 USB 埠與外接裝置，啟用全碟加密
  • 螢幕自動鎖定，落實桌面淨空
  • 定期教育訓練，防範尾隨進入等社交工程

聲明

通过实施这些策略并保持警惕，组织可以降低物理入侵的可能性，并减轻其对运营和安全的潜在影响。物理安全应与整体网络安全措施相结合，以提供全面的威胁防护。
